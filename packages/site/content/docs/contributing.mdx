# Contributing

Thank you for your interest in contributing to MotionScript! This guide covers how to set up the development environment, understand the repo structure, and submit changes.

## Repository structure

```
motion-script/
├── packages/
│   ├── core/          # @motion-script/core — the animation engine
│   ├── skia-render/   # @motion-script/skia-render — the Skia renderer
│   ├── web/           # @motion-script/web — browser backend, exporter, audio
│   ├── canvaskit/     # @motion-script/canvaskit — Skia CanvasKit (WASM)
│   ├── cli/           # @motion-script/cli — the `ms` headless renderer
│   ├── react/         # @motion-script/react — React bindings
│   ├── motion-script/ # motion-script — the flagship bundle
│   ├── create/        # create-motion-script — project scaffolding
│   ├── site/          # This documentation site
│   ├── template/      # Example project / testbed
│   ├── e2e/           # Visual regression tests
│   └── components/
│       ├── latex/     # @motion-script/latex
│       └── code/      # @motion-script/code
```

The monorepo uses [pnpm workspaces](https://pnpm.io/workspaces) and [Turborepo](https://turbo.build/).

## Getting started

### Prerequisites

- **Node.js** 18 or later
- **pnpm** 9 or later

```bash
npm install -g pnpm
```

### Install dependencies

```bash
pnpm install
```

### Build the libraries

Everything else depends on the prebuilt `dist/` of the library packages. Build
them first:

```bash
pnpm build:lib
```

### Start the docs site

```bash
pnpm --filter @motion-script/site dev
```

### Render the example project

There is no dev server to start — rendering is what you run:

```bash
pnpm --filter @motion-script/template exec ms list
pnpm --filter @motion-script/template exec ms screenshot last
```

Frames land in `packages/template/out/screenshots/`.

## Development workflow

### Making changes to core

After editing `packages/core/src`, rebuild the package:

```bash
pnpm --filter @motion-script/core build
```

Or run the watch mode:

```bash
pnpm --filter @motion-script/core dev
```

:::info Rebuild before rendering
`ms` renders against each package's built `dist/`, so rebuild the package you
edited before running it again. The one exception is `packages/cli/harness/`,
which Vite serves straight from source.
:::

### Running tests

```bash
pnpm test
# or run tests for a specific package
pnpm --filter @motion-script/core test
```

### Type checking

```bash
pnpm typecheck
```

## Submitting a pull request

1. **Fork** the repository on GitHub.
2. Create a branch from `main`: `git checkout -b feat/my-feature`.
3. Make your changes and ensure tests pass: `pnpm test`.
4. Commit with a descriptive message.
5. Push and open a pull request against `main`.

### What makes a good PR

- Focused changes: one concern per PR
- Tests for new behaviour
- Updated docs if you added or changed a public API
- No breaking changes without a discussion issue first

## Adding a new node

1. Create `packages/core/src/nodes/<category>/<name>-node.ts`.
2. Extend `ShapeNode<YourProps>` and implement `renderSelf(draw: RenderContext2D)`.
3. Export from `packages/core/src/nodes/index.ts`.
4. Add a page under `packages/site/content/docs/nodes/`.

## Adding a new image filter

1. Create `packages/core/src/attributes/shape/filters/implementations/<name>.ts`.
2. Implement the `FilterRegistry.register<YourFilter>(...)` call with a `lerp` and `equals` function.
3. Add the type to `ImageFilters` in `packages/core/src/attributes/shape/filters/chain.ts`.
4. Add a page under `packages/site/content/docs/image-filters/`.

## Adding a new node effect

1. Create `packages/core/src/attributes/shape/effects/implementations/<name>.ts`.
2. Register it with the effect registry and add to `Effects` in `packages/core/src/attributes/shape/effects/chain.ts`.
3. Add a page under `packages/site/content/docs/effects/`.

## Code style

- TypeScript strict mode throughout
- No comments unless the WHY is non-obvious
- Prefer editing existing files over creating new ones
- Run `pnpm lint` before committing
