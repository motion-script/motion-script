# 3D Graphics

MotionScript draws 3D with the same split it uses for everything else. You describe a scene as plain data, and the renderer turns it into pixels. Nothing in your project imports a 3D engine.

```tsx
import {
  Canvas3D, PerspectiveCamera3D, AmbientLight3D, DirectionalLight3D, Box3D,
} from 'motion-script';

<Canvas3D width={1600} height={900}>
  <PerspectiveCamera3D position={[0, 2, 6]} lookAt={0} fov={45} />
  <AmbientLight3D intensity={0.4} />
  <DirectionalLight3D intensity={2.4} position={[4, 6, 3]} />
  <Box3D width={2} color="tomato" roughness={0.3} />
</Canvas3D>
```

That is a complete 3D scene: a camera, two lights and a lit cube.

## A 3D scene is a tree

Everything in a 3D scene is a node, and a 3D node is a node in every sense that matters. It takes a `ref`, it holds children, it reads context, it has its own clock, and it animates with the same `to()` you use everywhere else:

```tsx
const rig = createRef<Group3D>();

<Canvas3D width="fill" height="fill">
  <PerspectiveCamera3D position={[0, 2, 6]} lookAt={0} />
  <AmbientLight3D intensity={0.4} />

  <Group3D ref={rig}>
    <Box3D width={2} color="tomato" />
    <Sphere3D radius={0.8} position={[3, 0, 0]} />
  </Group3D>
</Canvas3D>

yield* rig().to({ rotation: [0, 360, 0] }, 2);
```

Moving the `Group3D` moves everything under it, so a rig animates as one thing.

## Two trees, one API

The scene graph is one tree over two spaces:

* **`Node2D`** — laid out in a box on the page. Everything with a `width`, an anchor or a fill.
* **`Node3D`** — placed in space by a position, a rotation and a scale. Meshes, lights, cameras, fog.

They share a base, `Node`, which is where the tree itself lives along with reactive props, commands, context and the clock. What differs is only the two things that genuinely differ: how a node is placed, and how it draws.

The two never mix. Putting a `Box3D` inside a `Rect` throws, with a message pointing you at the one node that holds both.

## `Canvas3D` is where the two meet

`Canvas3D` is a `Rect` that hosts a 3D scene. Its `Node3D` children describe the scene; its `Node2D` children draw over the result as a HUD:

```tsx
<Canvas3D width="fill" height="fill" cornerRadius={24}>
  <PerspectiveCamera3D position={[0, 2, 6]} lookAt={0} />
  <AmbientLight3D intensity={0.4} />
  <Box3D width={2} color="tomato" />

  <Text text="FPS 60" fontSize={32} />
</Canvas3D>
```

Being a `Rect` is what makes it lay out in flex and stack groups, take `cornerRadius` and `clip`, and be masked, blended and filtered like anything else.

## 3D is still a fill

Underneath, a 3D scene is a **fill**, the same as a colour, a gradient or an image: the renderer draws it to a texture and paints it through whatever shape asked for it. `Canvas3D` is convenience on top of that, not machinery.

That is what lets 3D clip to shapes a rect cannot describe. Build the scene by hand as a `Scene3D` — which is exactly what `Canvas3D` produces internally — and use it as a fill:

```tsx
const scene = new Scene3D()
  .perspective({ position: [0, 2, 6], lookAt: 0, fov: 45 })
  .light({ type: 'ambient', intensity: 0.4 })
  .draw(new Graphics3D().box({ width: 2, color: 'tomato' }));

<Ellipse width={420} height={420} fill={scene} />
<Text text="DEPTH" fontSize={320} fill={scene} />
<Rect fill={['#0b0d12', scene]} />
```

A bare `Scene3D` coerces to a 3D fill the same way a bare CSS string coerces to a solid colour. Because it is one layer in the fill array, paint order, `opacity` and `blend` work as usual.

## The three values

Three names come up constantly, and they divide cleanly:

| | what it is |
|---|---|
| `Graphics3D` | what **one node** draws — geometry and material. The 3D `Graphics2D`. |
| `RenderContext3D` | what a node draws **into**. Lights, camera and scene settings are calls on it. |
| `Scene3D` | the **recorded** result: camera, lights, fog and every drawable, ready to paint. |

You rarely touch any of them directly. They matter when you write a custom 3D node, which is the same shape as a custom 2D node:

```tsx
class Blob3D extends Node3D {
  protected renderSelf(ctx: RenderContext3D): void {
    ctx.draw(new Graphics3D().sphere({ radius: 1, color: 'red' }));
  }
}
```

## Angles are degrees

Every angle in the 3D API — Euler rotations, spot cone angles, sweep arcs, texture rotation — is in degrees, matching 2D `rotation`. You never write `Math.PI`.

## What is cheap to animate

Transforms, material values and light values are written in place every frame, so they cost nothing. **Geometry parameters are not**: the underlying geometries are immutable, so tweening a `radius` rebuilds the mesh each frame. Scale the object instead:

```tsx
{/* expensive — rebuilds the box every frame */}
<Box3D width={() => grow()} />

{/* cheap — one matrix write */}
<Box3D width={1} scale={() => [grow(), 1, 1]} />
```
