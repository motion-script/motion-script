# Animating

3D nodes animate the way every other node does. Bind a prop to a signal, or hold a ref and call `to()`:

```tsx
const spin = createSignal(0);

<Canvas3D>
  <PerspectiveCamera3D position={[0, 2, 6]} lookAt={0} />
  <DirectionalLight3D intensity={2} position={[4, 6, 3]} />
  <Box3D width={2} color="tomato" rotation={() => [0, spin(), 0]} />
</Canvas3D>

yield* spin(360, 2, easeInOut('quad'));
```

Or, without a signal at all:

```tsx
const box = createRef<Box3D>();

<Box3D ref={box} width={2} color="tomato" />

yield* box().to({ rotation: [0, 360, 0], color: 'cyan' }, 2, easeInOut('quad'));
```

The scene is rebuilt from scratch every frame, so nothing accumulates: frame 10 looks the same whether you played to it or scrubbed back to it.

## Signals need a lerp for non-numbers

A signal holding a number interpolates for free. A signal holding anything else needs an explicit lerp, or it will **snap at the end of the tween instead of interpolating**. There is no error, so this is easy to miss.

```tsx
import { createSignal, lerpVector3, lerpEuler3, slerpQuaternion } from 'motion-script';

const spin = createSignal(0);                                        // fine
const pos  = createSignal({ x: 0, y: 0, z: 0 }, lerpVector3);        // needs the lerp
const rot  = createSignal({ x: 0, y: 0, z: 0 }, lerpEuler3);         // needs the lerp
const quat = createSignal(IDENTITY_QUATERNION, slerpQuaternion);     // needs the lerp
```

Use `slerpQuaternion` with a `quaternion` for tumbles where Euler interpolation would gimbal lock.

## There is no `t`

A `prop={() => ...}` binding re-evaluates when the **signals** it reads change. `time.elapsed` is a plain field, not a signal, so this computes once and freezes:

```tsx
{/* Wrong. Runs once, then never again. No error, just a still image. */}
<Box3D rotation={() => [0, this.time.elapsed * 90, 0]} />
```

Two correct options:

* Drive the motion from a tweened signal. This also puts it on the timeline, so it scrubs.
* Read `this.time.elapsed` inside `renderSelf()` or `buildScene3D()`, which do re-run every frame.

```tsx
class Spinner extends Node3D {
  protected override renderSelf(ctx: RenderContext3D): void {
    const t = this.time.elapsed;
    ctx.draw(new Graphics3D().box({ width: 2, rotation: [0, t * 90, 0] }));
  }
}
```

## Prefer signals over the clock

A signal is usually the better choice even when the clock would work. A tweened signal is part of the timeline, so it scrubs, exports and previews consistently, and its speed is described in the scene rather than derived from wall time.

```tsx
const phase = createSignal(0);

// A travelling wave, driven linearly across the scene
yield* phase(20, 4, linear());
```

## What is cheap to change

Not every field costs the same per frame.

| Kind of change | Cost | Notes |
|---|---|---|
| Transforms | Free | `position`, `rotation`, `scale`, `lookAt` are in-place writes |
| Material and light values | Free | Colours, intensities, `roughness`, `opacity` |
| Shader uniform values | Free | The program is not recompiled |
| Geometry parameters | Expensive | Geometries are immutable, so the mesh is reallocated every frame |
| Structural material fields | Expensive | Recompiles the shader program |

The trap is geometry. A bound `width` on a `Box3D` rebuilds the geometry every frame. Scale the object instead:

```tsx
{/* Slow — rebuilds the geometry every frame */}
<Box3D width={() => size()} />

{/* Fast, same result — one matrix write */}
<Box3D width={1} scale={() => [size(), 1, 1]} />
```

The same applies to sphere `radius`, torus `tube` and every other geometry parameter. Model the change as a transform where you can.

Structural material fields are ones that change how the shader is built rather than what it is fed, such as `vertexColors`, `flatShading` and turning shadows on. Set them once rather than tweening them.

## Keys

The renderer caches one live GPU object per node and mutates it between frames rather than rebuilding it. Identity comes from **the node itself**, so a conditional sibling appearing or disappearing costs nothing:

```tsx
<Canvas3D>
  {showFloor && <Plane3D width={60} height={60} rotation={[-90, 0, 0]} />}

  {screens.map(screen => (
    <Group3D position={[screen.x, 0, 0]}>
      <Box3D width={4} height={2.4} color="#15181f" />
    </Group3D>
  ))}
</Canvas3D>
```

There is nothing to declare: adding or removing the floor leaves every monitor's cached geometry alone, because their identity never depended on their position in a list.

A single node that draws several things through one `Graphics3D` numbers them positionally within that node. That is stable as long as the node emits the same drawables in the same order; when it emits them conditionally, set `key` on the transform to pin identity.

## Cameras animate like anything else

The camera is a node, so orbiting is arithmetic on a signal:

```tsx
const angle = createSignal(0);   // degrees

<PerspectiveCamera3D
  position={() => {
    const a = (angle() * Math.PI) / 180;
    return [Math.cos(a) * 12, 5, Math.sin(a) * 12];
  }}
  lookAt={0}
  fov={45}
/>

yield* angle(360, 6, easeInOut('quad'));
```

Or put it inside a `Group3D` and rotate the group, which needs no trigonometry at all:

```tsx
<Group3D ref={rig}>
  <PerspectiveCamera3D position={[0, 5, 12]} lookAt={0} />
</Group3D>

yield* rig().to({ rotation: [0, 360, 0] }, 6, easeInOut('quad'));
```

When an object moves, aim the camera at it rather than at the origin, or it will leave the frame:

```tsx
<PerspectiveCamera3D position={[0, 2.5, 6]} lookAt={() => lift()} fov={45} />
```

## Animating a component's props

For a reusable component, put the knobs on the node with `@property` and animate them with `.to()`, exactly as for any other custom node:

```tsx
class Turntable extends Canvas3D<TurntableProps> {
  @property({ default: 0 }) declare orbit: number;
  @property({ default: 8 }) declare zoom: number;

  protected override buildScene3D(): Scene3D {
    const a = (this.orbit * Math.PI) / 180;
    return new Scene3D()
      .perspective({ position: [Math.cos(a) * this.zoom, 2, Math.sin(a) * this.zoom], lookAt: 0 })
      .light({ type: 'directional', intensity: 2 }, { position: [4, 6, 3] })
      .draw(new Graphics3D().torus({ radius: 1.5, tube: 0.4, color: 'tomato' }));
  }
}

yield* table().to({ orbit: 180, zoom: 5 }, 4, easeInOut('quad'));
```

Non-numeric props need a `tween`, including booleans, since `.to()` only drives keys that are numeric or carry one. See [Properties](../properties).
