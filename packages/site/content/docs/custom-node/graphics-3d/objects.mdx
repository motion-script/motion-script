# Objects

Everything you put in a 3D scene: meshes, groups, and the specialised drawables for crowds, lines, sprites and loaded models.

## Meshes

Fourteen mesh nodes, each taking its geometry's own parameters alongside a placement and a material — all as ordinary props, so any of them can be bound or tweened.

```tsx
<Box3D width={2} height={2} depth={2} color="tomato" roughness={0.3} position={[0, 1, 0]} />
```

| Node | Main parameters |
|---|---|
| `Box3D` | `width`, `height`, `depth`, `widthSegments`, `heightSegments`, `depthSegments` |
| `Sphere3D` | `radius`, `widthSegments`, `heightSegments`, `phiStart`, `phiLength`, `thetaStart`, `thetaLength` |
| `Plane3D` | `width`, `height`, `widthSegments`, `heightSegments` |
| `Cylinder3D` | `radiusTop`, `radiusBottom`, `height`, `radialSegments`, `openEnded` |
| `Cone3D` | `radius`, `height`, `radialSegments`, `openEnded` |
| `Torus3D` | `radius`, `tube`, `radialSegments`, `tubularSegments`, `arc` |
| `TorusKnot3D` | `radius`, `tube`, `tubularSegments`, `radialSegments`, `p`, `q` |
| `Circle3D` | `radius`, `segments`, `thetaStart`, `thetaLength` |
| `Ring3D` | `innerRadius`, `outerRadius`, `thetaSegments`, `thetaStart`, `thetaLength` |
| `Capsule3D` | `radius`, `height`, `capSegments`, `radialSegments` |
| `Polyhedron3D` | `shape`, `radius`, `detail` |
| `Extrude3D` | `shape`, `depth`, `bevel`, `bevelThickness`, `bevelSize` |
| `Lathe3D` | `points`, `segments`, `phiStart`, `phiLength` |
| `Tube3D` | `points`, `radius`, `tubularSegments`, `radialSegments`, `closed` |

All angle parameters are degrees.

`Extrude3D` takes the same path data the 2D [`Path` node](/docs/nodes/path) takes, so an existing outline becomes a solid with no new vocabulary:

```tsx
<Extrude3D shape="M 0 -60 L 52 40 L -52 40 Z" depth={20} bevel bevelSize={2} />
```

## Placement

Every 3D node takes the same placement props — they are `Node3D`'s own, the way `x`/`y`/`width` are `Node2D`'s.

| Field | Type | Description |
|---|---|---|
| `position` | `Vector3Input` | Position in the parent's space |
| `rotation` | `Vector3Input \| Euler3` | Euler rotation in degrees |
| `quaternion` | `Quaternion` | Rotation as a quaternion. Wins over `rotation` |
| `scale` | `Vector3Input` | Per-axis scale, or one number for all three |
| `lookAt` | `Vector3Input` | Point to orient toward. Wins over both rotations |
| `visible` | `boolean` | Hide without removing |
| `castShadow` | `boolean` | Cast into shadow maps |
| `receiveShadow` | `boolean` | Receive shadows |
| `renderOrder` | `number` | Draw-order override for transparent sorting |


## Material shorthand

Every mesh node also takes the common material fields directly, so the usual case needs no separate material:

```tsx
<Sphere3D radius={1} color="cyan" roughness={0.2} metalness={0.8} />
<Plane3D width={10} height={10} color="#11141c" roughness={0.85} />
<Torus3D radius={1.4} tube={0.08} unlit color="white" />
```

`color`, `opacity`, `transparent`, `roughness`, `metalness`, `emissive`, `emissiveIntensity`, `map`, `normalMap`, `roughnessMap`, `metalnessMap`, `aoMap`, `alphaMap`, `envMapIntensity`, `wireframe`, `flatShading`, `side`, `vertexColors`, `depthWrite`, `depthTest`, `blending`, `alphaTest` and `toneMapped` are all accepted this way.

`unlit` uses a `basic` material instead of `standard`, which is right for anything that should read as its own light source rather than being shaded by the scene.

For full control, pass a `material` built with `Mat`. See [Materials and textures](./materials).

## Groups

`Group3D` nests objects so they inherit its transform — the 3D `Rect` that only groups.

```tsx
<Group3D position={[3, 0, 0]} rotation={[0, 45, 0]}>
  <Sphere3D radius={0.8} color="cyan" />
  <Box3D width={0.4} position={[0, 1.2, 0]} />
</Group3D>
```

Hold it with a ref and the whole rig animates as one thing:

```tsx
const rig = createRef<Group3D>();
yield* rig().to({ rotation: [0, 360, 0], position: [0, 2, 0] }, 2);
```

## Explicit geometry and material

`Mesh3D` takes a geometry and a material as separate values, built with `Geo` and `Mat`. Hoist them and share them across meshes, since the renderer uploads a shared geometry to the GPU once no matter how many meshes reference it:

```tsx
import { Geo, Mat } from 'motion-script';

const brick = Geo.box({ width: 1, height: 0.5, depth: 0.5 });
const red = Mat.standard({ color: 'tomato', roughness: 0.4 });

<Mesh3D geometry={brick} material={red} position={[0, 0, 0]} />
<Mesh3D geometry={brick} material={red} position={[1, 0, 0]} />   {/* same GPU buffer, same shader */}
```

`Geo` also has entries the mesh nodes do not: `tetrahedron`, `octahedron`, `icosahedron`, `dodecahedron`, `buffer`, `parametric`, `edges`, `wireframe` and `model`. Reach them through `Mesh3D`.

### `Geo.buffer`

Raw vertex data, for any mesh you can compute:

```tsx
Geo.buffer({
  position: [/* x, y, z, x, y, z, ... */],
  index: [/* triangle indices */],
  computeNormals: true,
})
```

`normal`, `uv` and `color` are optional. Set `staticData: true` once the arrays stop changing so the renderer skips re-uploading them, and bump `revision` when you mutate an array in place.

### `Geo.parametric`

A surface sampled over a grid, which is the friendlier form of `Geo.buffer` for waves, terrain and ribbons:

```tsx
Geo.parametric({
  segments: [70, 70],
  vertex: (u, v) => {
    const x = (u - 0.5) * 20;
    const z = (v - 0.5) * 20;
    return { x, y: wave(x, z, phase()), z };
  },
  color: (u, v, p) => heightColor(p.y),
  computeNormals: true,
})
```

`u` and `v` both run from 0 to 1. The callbacks are evaluated into vertex buffers when you record the op, so the descriptor stays plain data. Per-vertex colour needs `vertexColors: true` on the material.

### `Geo.edges` and `Geo.wireframe`

Derived line geometry from another geometry. `edges` gives the hard edges only, which is a clean outline. `wireframe` gives every triangle edge.

```tsx
<Line3D
  geometry={Geo.edges(Geo.box({ width: 4, height: 4, depth: 4 }))}
  mode="segments"
  color="white"
  opacity={0.4}
/>
```

## Instances

Thousands of copies of one geometry in a single draw call. This is how you put a crowd on screen, since one mesh per copy will not keep up.

```tsx
<Instances3D
  geometry={Geo.box({ width: 0.2 })}
  material={Mat.standard({ color: 'cyan' })}
  instances={positions.map(p => ({ position: p, rotation: [0, p.x * 20, 0] }))}
  colors={tints}
/>
```

The instance array's length is the instance count. Each entry is a full placement. `colors` tints per instance and needs a material that reads instance colour.

## Lines

```tsx
<Line3D points={[[0, 0, 0], [1, 2, 0], [3, 1, 2]]} color="#6990DD" width={2} />
<Line3D geometry={Geo.edges(box)} mode="segments" color="white" opacity={0.4} />
```

| Prop | Type | Default | Description |
|---|---|---|---|
| `points` | `Vector3Input[]` | – | Explicit points. Give either this or `geometry` |
| `geometry` | `Geometry3D` | – | A geometry to draw as lines |
| `mode` | `'strip' \| 'segments' \| 'loop'` | `'strip'` | Connect in order, as disjoint pairs, or closed |
| `color` | `Color` | – | Shorthand for a line material |
| `width` | `number` | – | Line width |
| `dashed` | `boolean` | `false` | Use a dashed line material |

## Points

A point cloud, one dot per vertex of the geometry:

```tsx
<Points3D geometry={Geo.buffer({ position: cloud })} material={Mat.points({ size: 0.05, color: 'white' })} />
```

## Sprites

A camera-facing textured quad, which always presents flat to the viewer:

```tsx
<Sprite3D map="spark.png" position={[0, 2, 0]} scale={0.5} />
```

## Models

Load a glTF, GLB or OBJ file:

```tsx
<Model3D src="robot.glb" position={[0, 0, 0]} scale={0.5} />
```

| Prop | Type | Description |
|---|---|---|
| `src` | `string` | Path in the asset manifest |
| `animation` | `ModelAnimation3D \| ModelAnimation3D[]` | Clips to sample |
| `override` | `Record<string, Material3D>` | Replace materials by mesh or material name |

Baked animation is sampled at an explicit time rather than advanced by a delta, which is what keeps a model frame-identical when you scrub:

```tsx
.model({
  src: 'robot.glb',
  animation: [{ clip: 'Walk', time: walkTime(), weight: 1 }],
})
```

`clip` is a name or an index, and defaults to the first clip. Give several entries with `weight` values to cross-fade between them.
