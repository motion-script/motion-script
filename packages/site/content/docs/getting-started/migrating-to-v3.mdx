# Migrating to v3

v3 makes the scene graph one tree API over two spaces. A 3D scene is now written
as a tree of nodes rather than as a builder chain, and those nodes get everything
a 2D node has: refs, `to()`/`set()`/`save()`/`restore()`, signal bindings, context,
per-node clocks, and composition by subclassing.

Making room for that meant renaming the things that were implicitly "the 2D one".
Every change is mechanical, and your editor's rename will do most of it.

## The renames

| before | after |
|---|---|
| `Node` | `Node2D` |
| `NodeProps` | `Node2DProps` |
| `Graphics` | `Graphics2D` |
| `RenderContext` | `RenderContext2D` |
| `View3D` | `Canvas3D` |
| `View3DProps` | `Canvas3DProps` |
| `Fills.view3D(g3)` | `Fills.canvas3D(scene)` |

`Node` still exists — it is now the **shared base** of `Node2D` and `Node3D`, and
holds everything that is true of a node whichever space it lives in. Custom 2D
nodes extend `Node2D`:

```ts
// before
class Blob extends Node {
    protected renderSelf(ctx: RenderContext): void {
        ctx.draw(new Graphics().rect({ width: 200 }).fill("red"));
    }
}

// after
class Blob extends Node2D {
    protected renderSelf(ctx: RenderContext2D): void {
        ctx.draw(new Graphics2D().rect({ width: 200 }).fill("red"));
    }
}
```

`Render2DContext` is gone; its one method now lives on `RenderContext2D` directly.

## JSX is typed as `Node`

One JSX runtime serves both trees, so a JSX expression is typed as the shared base.
If you annotate your own JSX, widen the annotation:

```ts
// before
function card(label: string): Node { … return <Rect>…</Rect>; }

// after — `Node` is still the right answer, it just means something broader now
function card(label: string): Node { … return <Rect>…</Rect>; }
```

The change bites where you wrote the *narrow* type explicitly:

```ts
// before
const children: Node2D[] = [];          // was `Node[]`, i.e. the 2D base
children.push(<Rect />);                // ✗ v3: JSX is `Node`, not `Node2D`

// after
const children: Node[] = [];
children.push(<Rect />);                // ✓
```

Library surfaces that receive JSX — `stage.add`, a project's `backgrounds` /
`overlays`, `Tex.surface` — already take `Node`. Handing one a 3D node throws with
a clear message rather than silently drawing nothing.

## 3D: from a builder to a tree

`Graphics3D` is now *what one node draws* — geometry and material, the way
`Graphics2D` is shapes and paint. Everything that belongs to the scene rather than
to a thing in it is a node:

```tsx
// before
<View3D
    width="fill" height="fill" cornerRadius={24}
    graphics3D={() => new Graphics3D()
        .perspective({ position: [0, 2, 6], lookAt: 0, fov: 45 })
        .ambient({ intensity: 0.4 })
        .directional({ intensity: 2.4, position: [4, 6, 3] })
        .fog({ type: "linear", color: "#0b0d12", near: 5, far: 30 })
        .box({ width: 2, color: "tomato", rotation: [0, spin(), 0] })
        .group({ position: [3, 0, 0] }, g3 => g3.sphere({ radius: 0.8 }))}
/>

// after
<Canvas3D width="fill" height="fill" cornerRadius={24}>
    <PerspectiveCamera3D position={[0, 2, 6]} lookAt={0} fov={45} />
    <AmbientLight3D intensity={0.4} />
    <DirectionalLight3D intensity={2.4} position={[4, 6, 3]} />
    <Fog3D color="#0b0d12" near={5} far={30} />

    <Box3D width={2} color="tomato" rotation={() => [0, spin(), 0]} />
    <Group3D position={[3, 0, 0]}>
        <Sphere3D radius={0.8} />
    </Group3D>
</Canvas3D>
```

Every builder method has a node:

| `Graphics3D` method | node |
|---|---|
| `.box`, `.sphere`, `.plane`, `.cylinder`, `.cone`, `.torus`, `.torusKnot`, `.circle`, `.ring`, `.capsule`, `.polyhedron`, `.extrude`, `.lathe`, `.tube` | `Box3D`, `Sphere3D`, `Plane3D`, … |
| `.mesh(geometry, material)` | `<Mesh3D geometry material />` |
| `.instances`, `.points`, `.line`, `.sprite`, `.model` | `Instances3D`, `Points3D`, `Line3D`, `Sprite3D`, `Model3D` |
| `.ambient`, `.hemisphere`, `.directional`, `.point`, `.spot`, `.rectArea` | `AmbientLight3D`, `HemisphereLight3D`, `DirectionalLight3D`, `PointLight3D`, `SpotLight3D`, `RectAreaLight3D` |
| `.perspective`, `.orthographic` | `PerspectiveCamera3D`, `OrthographicCamera3D` |
| `.fog`, `.background`, `.environment`, `.shadows`, `.tone`, `.post` | `Fog3D`, `Background3D`, `Environment3D`, `Shadows3D`, `ToneMapping3D`, `PostEffects3D` |
| `.group(transform, build)` | `<Group3D {...transform}>…</Group3D>` |

Because they are nodes, they animate like nodes:

```tsx
const rig = createRef<Group3D>();

<Group3D ref={rig}><Box3D width={2} /></Group3D>

yield* rig().to({ rotation: [0, 360, 0], position: [0, 1, 0] }, 2);
```

Geometry parameters are still the expensive thing to animate — three's geometries
are immutable, so a tweened `radius` reallocates the mesh every frame. Tween
`scale` instead.

## 3D through an arbitrary shape

Still supported, and still the reason 3D is a fill rather than a special node. What
you hand to the fill is a recorded `Scene3D` — which is exactly what a `Canvas3D`
produces internally:

```tsx
const scene = new Scene3D()
    .perspective({ position: [0, 0, 2.6], lookAt: 0, fov: 55 })
    .light({ type: "ambient", intensity: 0.4 })
    .light({ type: "directional", intensity: 2.4 }, { position: [2, 4, 3] })
    .draw(new Graphics3D().box({ width: 2.4, color: "#4f8ef7" }));

<Ellipse width={360} height={280} fill={scene} />
<Text text="DEPTH" fontSize={320} fill={Fills.canvas3D(scene)} />
```

A bare `Scene3D` coerces to a `canvas3D` fill the way a bare CSS string coerces to
a solid one, so `fill={scene}` and `fill={["#0b0d12", scene]}` both work.

Note the shape of `.light()`: a light's own parameters and its *placement* are
separate arguments, because placement is a transform. `.directional({ intensity,
position })` becomes `.light({ type: "directional", intensity }, { position })`.

## Reusable 3D components

`View3D` subclasses that overrode `buildGraphics3D()` become `Canvas3D` subclasses
that override `buildScene3D()`:

```ts
// before
class Turntable extends View3D {
    protected override buildGraphics3D(): Graphics3D {
        return new Graphics3D()
            .perspective({ position: orbit(this.angle), lookAt: 0 })
            .ambient({ intensity: 0.4 })
            .torus({ radius: 1.5, tube: 0.4, color: "tomato" });
    }
}

// after
class Turntable extends Canvas3D {
    protected override buildScene3D(): Scene3D {
        return new Scene3D()
            .perspective({ position: orbit(this.angle), lookAt: 0 })
            .light({ type: "ambient", intensity: 0.4 })
            .draw(new Graphics3D().torus({ radius: 1.5, tube: 0.4, color: "tomato" }));
    }
}
```

For a component that is a *thing in the scene* rather than a whole viewport,
subclass `Node3D` instead — that is the new, and usually better, option:

```ts
class Turntable extends Node3D {
    protected override renderSelf(ctx: RenderContext3D): void {
        ctx.draw(new Graphics3D().torus({ radius: 1.5, tube: 0.4, color: "tomato" }));
    }
}
```

## Descriptor types

The 3D descriptor interfaces took a `Data` infix so the node classes could have the
obvious names: `Light3D` → `LightData3D`, `AmbientLight3D` → `AmbientLightData3D`,
`Camera3D` → `CameraData3D`, `Fog3D` → `FogData3D`, and so on for
`Background3D`, `Environment3D`, `ShadowSettings3D`, `ToneMapping3D` and
`PostEffect3D`. `Geometry3D`, `Material3D`, `Texture3D` and `Transform3D` are
unchanged — no node took those names.

## Custom attribute properties

If you declared an optional attribute prop with `@colorProperty({ default: undefined })`
(or any other attribute decorator), it now stays genuinely undefined instead of
falling back to the attribute's built-in default. That is a fix — the old behaviour
turned "no colour set" into black — but if you were relying on the fallback, name it:

```ts
@colorProperty({ default: "white" }) declare tint: Color;
```

## The node API, tightened

The same pass that split `Node` in two also drew a line between what a *scene
author* calls and what the *runtime* calls. Most of it is renames; the rest
removes a second way of spelling something that already had one.

### Renames

| before | after |
|---|---|
| `RootNode` / `RootProps` | `Canvas2D` / `Canvas2DProps` |
| `BuildStage` | `CanvasStage` (and `Stage` is now a hand-written interface) |
| `scene.root` / `stage.root` | `scene.canvas` / `stage.canvas` |
| `Measurer` (and the deprecated `MeasureScope`) | `Measurer2D` |
| `AssetCatalog` (class) | `AssetCatalog` (interface) + `ManifestAssetCatalog` |
| `AssetTracker` (class) | `AssetTracker` (interface) + `CanvasAssetTracker` |
| `RenderContext2D` (abstract class) | `RenderContext2D` (interface) + `CanvasRenderContext2D` |
| `node.layoutRect` / `node.measuredRect` | `node.layoutBounds` (one member, now public) |
| `node.clock` / `NodeClock` | `node.time` / `NodeTime` (`.time` → `.total`) |
| `onRender(ctx)` | `renderContent(ctx)` — or just override `renderSelf` |
| `ctx.beginEffectScope` / `endEffectScope` | `ctx.beginEffects` / `ctx.endEffects` |
| `ctx.rasterizeOffscreen` | `ctx.rasterize` |
| `ctx.defaultTextStyle()` | `ctx.defaultTextStyle` (a property) |
| `this.animate(at, …)` (custom commands) | `this.command(at, …)` |

`measureText` now returns a `Size2D` rather than a bare width — the shaper always
knew both, and reconstructing a height from `fontSize × lineHeight` disagreed with
it for any fallback face. Read `.width` where you read a number before.

### One command per `to()`

`node.to(...)` used to return a builder you could append to. It is now a single
`Command`. Sequence with `sequence(...)`:

```ts
// before
yield* node.to({ x: 100 }, 1).to({ x: 0 }, 1);

// after
yield* sequence(node.to({ x: 100 }, 1), node.to({ x: 0 }, 1));
```

Every command-shaped method now carries `@command()`, so `getCommandMeta(node)`
lists them all — `to`, `restore`, `moveTo`, `fadeTo`, `rotateTo`, `scaleTo`,
`addChildAt`, `removeChildAt`, `reparent`, plus each node's own.

### `attach()` replaces three calls

`bindAssets`, `bindContext` and `ellapse` were three walks a host had to make in
the right order every frame. They are one:

```ts
// before
scene.bindAssets(catalog);
scene.bindContext(ContextMap.EMPTY, false);
scene.ellapse(time);

// after
scene.attach({ assets: catalog, context: ContextMap.EMPTY, time });
```

`attach` is also what sets `node.mounted`, and **`mounted` gates everything**: a
node outside the tree measures nothing, lays out nothing, renders nothing,
declares no assets, and its commands run their duration while writing nothing. If
a tween of yours stopped doing anything, the node is not in the tree yet.

### `add` / `remove` / `clear`

| before | after |
|---|---|
| `node.addChild(x)` / `node.addChildren([x, y])` | `node.add(x)` / `node.add([x, y])` |
| `node.removeChild(x)` | `node.remove(x)` |
| `node.clearChildren()` | `node.clear()` |
| `code.remove(lines(2), 0.4)` | `code.erase(lines(2), 0.4)` |

`add` and `remove` take the same shapes the `children` prop does — a node, an
array, or a nested one, with `false`/`null` entries dropped. The three older
methods are private now: `add` already did everything they did and more.

`Code.remove` had to move because a `Code` is also a node, and one object cannot
usefully have two `remove`s.

### The per-frame walks left the node

Four members were pure subtree traversals that happened to live on `Node`. They
are free functions now, in `nodes/node/node-walk.ts`:

| before | after |
|---|---|
| `node.prepareLayoutAssets(tracker)` | `declareLayoutAssets(node, tracker)` |
| `node.prepareRenderAssets(tracker, path)` | `declareRenderAssets(node, tracker, path)` |
| `node.sample()` | `sampleTree(node)` |
| `node.primeMotion(at)` | `primeMotionTree(node, at)` |

The hooks they call — `prepareLayout(tracker)` and `prepareRender(tracker)` —
are unchanged, and are still what a custom node overrides. That pairing is why
they moved: `prepareRenderAssets` sat one letter from `prepareRender` in every
node's autocomplete, and the two are not interchangeable.

`beforeRender`, `afterRender`, `renderChildren` and `resolveSizeInput` became
`protected`. Overriding them is unchanged; calling them on another node was never
supported.

### Removed

- **`node.wiggle(...)`**, and with it **`node.random`** and the **`seed` prop**.
  Randomness lives on the stage: `stage.random(seed)` hands back a source that is
  rewound before every replay, which is what makes a draw reproducible across a
  scrub. A node with a private source was only reproducible for as long as
  nothing above it changed how many times it was built.
- **`node.moveX(x, …)` / `node.moveY(y, …)`** — write `node.to({ x }, …)`.
- **`node.reinit()`** — a `Scene` now builds a *fresh* `Canvas2D` on every
  `reset()` instead of rewinding the old one, so there is nothing to re-init.
- **`ctx.begin` / `ctx.end`** are off `RenderContext2D`. They bracket a node's
  draw scope and belong to `Node2D.render`; a `renderSelf` that opened one left
  every later sibling inside it. A host driving a render pass holds a
  `RenderPass2D`, which still has them.

### Global layers must be factories

```ts
// before — a node built at module scope
overlays: [<Watermark />]

// after
overlays: [() => <Watermark />]
```

The project module is evaluated before the theme is registered, so a node built
inline resolves its tokens against an empty registry; and a layer built once is
shared between runtimes, so the first to dispose leaves the next with a hollow
tree. Passing a node now throws at construction instead of failing quietly on the
second mount.
